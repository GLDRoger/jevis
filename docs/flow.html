What Jevis does at each step

Jevis watches a coding agent at six moments. At each one it reads what is happening, asks Jev (a fast yes-or-no model) a set of questions, and either stays quiet or steers: it names what the agent is doing wrong and what to do instead.

  • Adds a notenothing is stopped
  • Refuses the callthe command or edit does not run
  • Sends it backthe agent cannot finish yet
  • Stays quietthe usual result

Secrets never leave the machine

Before Jev or the critic sees anything, Jevis masks private keys (SSH, PEM, PGP), card numbers that pass the Luhn check and their security codes, passwords in assignments, JSON, flags, URLs and headers, and provider tokens (OpenAI, Anthropic, Stripe, GitHub, AWS, Google, Slack and more). The name stays, so DB_PASSWORD=[redacted] still reads as a database login. The same mask applies to everything Jevis writes to disk.

When Jevis is unsure, it gets out of the way

No key, Jev down, a slow answer, a crash, or a critic that fails: every one of these ends in "stays quiet". Jevis sends a second request after 700 ms and takes whichever answers first, so a slow reply rarely costs a check. The worst case is the agent working as if Jevis were not there.

Why the limits exist

Four notes per message

A message can match a dozen lessons. Past four, the agent skims them all, and your own words get buried under Jevis's. So a message gets at most four notes and 3,000 characters, strongest first, and each note once per session. After the context is compacted, the agent has forgotten them, so they can come back.

Two send-backs per turn

The hook system Jevis replaces once held a session for hours over one wrong block. Jevis sends a turn back at most twice for its checks and twice for design review, and never for the same lesson twice in a turn. After that, the agent finishes and you decide.

"Did you ask for exactly this?"

Every refusal has a second question: did your message ask for exactly this? A force push you asked for goes through. A purple gradient your brand uses goes through. The rule catches defaults, not your decisions.

"Subagents spend the user's limits"

One lesson, not a setting. Astra, one of Codex's GPT-6 models, kept spinning up subagents for small jobs, and every one drew on your plan's usage. When you had not asked for delegation, that lesson reminds it that parallel agents cost you, so it works alone unless the job needs them.

Counts are from the wiki as of Sep 27 2026: 34 lessons for messages, 10 rules for commands (plus 4 optional destructive ones), 31 design-slop refusals for edits, 15 checks for turn endings.
